# Deviations from the proposal and the project brief

| # | Item | Planned | What was done | Why |
|---|---|---|---|---|
| D1 | Data | FeTS 2022 training data, 1,251 labeled cases, 23 institutions | Available since 2026-11-03 (data situation A): 1,251 labeled cases plus the partitioning CSV, and the 219 unlabeled validation cases | Earlier phases ran in situation C; superseded |
| D2 | Compute | Tier 1/2 GPU training | Tier 0: GTX 1650 Ti with 4 GB (about 3 GB usable under Windows), 7.4 GB RAM, CUDA torch | Hardware below the Tier 1 floor (8 GB). Scripts also run on a larger GPU (`docker/Dockerfile.train`) |
| D3 | Baseline ensemble | Proposal: "a five-model ensemble is the baseline predictor" | Per fold, `n_members` (default 3) seed replicates trained on the same fold split. Never an ensemble across folds | The brief's leakage rule forbids cross-fold ensembles for held-out evaluation. Seed replicates keep the deep-ensemble idea without leakage |
| D4 | Test-time adaptation | Proposal: "test-time adaptation of normalization statistics" | Entropy minimization of the instance-norm affine parameters (`src/btqc/infer/tta_adapt.py`) | nnU-Net uses instance normalization, so batch-norm statistic adaptation does not apply. Unit-tested on a small network; not run on nnU-Net models (none trained) |
| D5 | MaxStyle | Style augmentation with the authors' MaxStyle implementation | Fallback: random monotone Bezier intensity-curve style augmentation (`nnUNetTrainer_btqcStyle`) | MaxStyle needs an adversarial style generator with an auxiliary decoder optimized inside the training loop. Integrating it into nnU-Net's trainer was not feasible within the budget, and it could not be validated without data |
| D6 | Per-case standardization | Variants | Percentile clipping plus brain z-score (`pct`) and a mode/IQR variant (`mode`), written as a separate nnU-Net dataset | Per-case only, so no statistics leak across folds |
| D7 | Embedding shift | Fréchet distance of encoder bottleneck features | Implemented (`eval/shift.py::frechet_distance`, unit-tested); not run | Needs trained encoders |
| D8 | Trust gate location | Brief lists `uncertainty/failure_detection.py` | The gate lives in its own module `uncertainty/gate.py` with stdlib-only imports | Makes R4 checkable by a test that inspects the imports |
| D9 | Repository location | Project root folder | Sibling folder `D:\Foundation Project\brain-tumor-qc` | Keeps the data folder read-only (rule 6) |
| D10 | `make` | Makefile targets | Makefile delegates to `scripts/tasks.py` | `make` is not installed on the Windows machine. Both entry points run identical commands |
| D11 | HD95 penalty source | "BraTS uses a penalty value, check and cite" | 373.13 mm (grid diagonal), configurable | The value was not found in an official BraTS 2021 document. The same constant appears in published BraTS-family evaluations (arXiv:2410.22057), and BraTS 2023 glioma reports use 374. See `docs/metrics.md` |
| D12 | Validation-set predictions in the dashboard | Model output | Rule-based EXAMPLE outlines (`infer/example_rules.py`), labeled as examples everywhere | No trained model exists (rule 2) |
| D13 | Pipeline demo for the explorer | Real held-out results | A SYNTHETIC demo (`scripts/synthetic_demo.py`): fixtures plus a stub predictor derived from the reference masks, labeled SYNTHETIC | Shows the explorer and figure code working end to end without claiming results |
| D15 | Training budget | 4 methods x 5 site-held-out folds x 3 seeds x 100 epochs | One laptop run (2026-11-13): baseline only, fold `mid` held out (7 institutions, 216 cases), 1 seed, **10 epochs** of 250 iterations (~19 min/epoch, 3.1 h) | 24 h deadline on a 4 GB GPU. The full protocol would take about 58 h per method. nnU-Net's poly learning-rate schedule is scaled to the 10 epochs. Other methods and folds: not run |
| D16 | nnU-Net plans | `nnUNetPlans_4GB` (patch 96x128x96, batch 2) | `nnUNetPlans_3GB`: same plans and preprocessed data, patch **80x112x80**, batch 2; `cudnn.benchmark` off (`BTQC_CUDNN_BENCHMARK=0`) | The 4 GB plan and cuDNN's algorithm search ran the GPU out of memory at the first iteration |
| D17 | Test set size | Every val, insite_test and heldout case of each fold | **15 cases drawn from each** of val, insite_test and heldout of fold `mid` (seeded with `seed` from `configs/train.yaml`; `scripts/infer.py --per-split 15`), 45 cases in all. The 15 held-out cases cover all 7 held-out institutions | Inference time on the laptop GPU. Confidence intervals are wide; numbers are a pilot result |
| D14 | nnU-Net planning on all labeled cases | Not specified | Planning uses every case in `imagesTr`, held-out groups included | For MRI, nnU-Net normalizes per image (z-score), and every case has the same 1 mm grid, so only spacing and shape statistics are shared. No intensity or label statistics leak. Documented as a known minor coupling |
